# Tips

Below are some tips to keep in mind when thinking about suggesting a
change.

* Try to understand what is already there.

  Some sorts of changes might result in the loss of important /
  helpful information.  Such information might have a better home or
  perhaps it could be reworded.  It seems likely that in order to
  consider such matters appropriately, a sufficient understanding of
  what exists currently is needed.

  Apart from engaging with the content itself, it might also help
  to search / study:

  * Past issues and PRs at the janet and janet-lang.org repositories
  * Zulip discussions
  * GH discussions associated with the janet repository
  * Any related source code

  Asking other community members might also be helpful.

* Search the existing documentation to see if something is already
  covered.

  It could be that other locations might already cover what one
  thought was missing.  It could also be that other locations could do
  with being updated.  In short, it's probably better from a
  consistency perspective to consider where and how something might
  already have some coverage.

  Sometimes doing a local search may be more effective.  Some relevant
  locations include:

  * Website prose: janet-lang.org's `content` directory
  * Core API examples: janet-lang.org's `examples` directory
  * Docstrings: janet's `.c` files and `boot.janet`
  * Comments in source code: janet's source files

* Consider creating an issue to work on articulating clearly the
  motivation for certain changes.

  An issue can faciliate:

  * clarification of thought (e.g. externalization and getting feedback)
  * collecting relevant information in fewer locations
  * making it clearer what is being discussed
  * general communication (e.g. a link to the issue can be easily shared)
  * searching (e.g. future investigations and research)
  * referencing specifics in source code and tests
  * referencing in PRs to give background information

  It's not always needed though, but taking a moment to consider might
  be worthwhile.  If no related discussion has happened, that might be
  a point in favor of creating an issue.

  Note that apart from docstrings, for documentation matters, it's
  likely an appropriate repository to make issues at is the
  janet-lang.org repository (though not for spork).
